# 寄存器架构

软件访问入口只有本地 APB CSR。所有分组先经过管理授权；公开信息窗口的数据只读例外仍要求身份有效且范围合法。
参数化地址槽位固定，不随功能裁剪重排；未实现槽位必须报错而不能产生索引回绕。地址/位域结构由后续 SystemRDL owner 建模。

| 分组 | 所有权 | 激活/状态模型 | 访问与保护 |
|---|---|---|---|
| ID/CAPABILITY/MAP | FRONTEND/CSR | elaboration 固定，只读反映真实配置 | 仅指定基本信息可公开读，其余管理授权 |
| CONFIG | POLICY | shadow 可编辑，active 仅原子 commit 更新；reload 复制 active 到 shadow | 管理授权、端口/全局锁、完整性门控 |
| LOCK/VERSION/COMMIT_STATUS | POLICY | 锁只收紧；版本成功提交自然回绕；诊断状态独立于主错误原因 | 无软件解锁；普通诊断读取不因锁关闭 |
| ERROR/LOG | EVENTS | 首错保持、最近更新、读字0形成独立快照；FIFO 由显式 POP 管理 | 管理授权，记录容量不影响准入 |
| IRQ/ALERT | IRQ | 粘滞 RAW、独立 ENABLE、W1C 清除，新事件优先 | 管理授权；策略锁不阻止告警使能修改 |
| SAFETY | POLICY | FATAL 只可信复位清除，首故障位置保持 | 故障后仍可读诊断；配置写/reload/commit 被拒绝 |
| DEBUG | DFX | 授权统计、一次性武装、等待阈值与合成事件 | 管理 + 硬件授权；DFX_EN 裁剪不改变普通权限 |

## 配置一致性

提交命令处于单输入总线的串行事务序列中；处理提交时不存在此前尚未完成的下游访问。
全部目标先做合法性、锁和完整性检查，再原子激活。版本变化与后续 SETUP 准入绑定。
全局锁下仍允许进一步设置端口锁。日志/中断管理与政策锁分离，防止锁死诊断。

## 软件交互边界

软件先写完整 shadow，再提交并检查响应、提交状态、版本与 active 读回，最后设锁。
撤权只影响后续进入本 IP 的请求；停止此前已启动的 DMA 或外设任务属于系统软件责任。
同一 APB 被外设等待占用时，软件无法通过同口访问诊断；本架构不提供未声明的救援端口。
