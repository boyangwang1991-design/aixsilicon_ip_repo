# axi_channel_register_slice 需求合同

状态：规划需求草案；MIG-IP-AXI-001，版本 0.1.0。按用户明确要求从 CBB AXI-001 迁入 IP。

## 功能边界

对一个 AXI 通道的 payload 与全部侧带进行一致缓冲，接受事件仅由该通道 valid 与 ready 共同决定。

背压期间 valid 及 payload 保持稳定；不关联五通道事务，不执行地址解码、突发管理或 AXI 响应生成。

该核只覆盖单一 AXI 通道；IP 仓内 axi_register_slice 负责完整五通道接口。
本次迁移改变仓库归属，不添加空包装，也不扩展为完整五通道事务管理。

## 需求与验收

- REQ-001：仅在 valid 与 ready 同时有效时接受一次传输；验证随机背压下无丢失、无重复、保序。
- REQ-002：payload 包含所选通道的全部侧带，停顿时 valid 与 payload 保持；逐字段验证对齐。
- REQ-003：前向、后向、完整切分作为显式静态模式；每个支持模式声明前后向组合路径、容量、L 与 II。
- REQ-004：反向 ready 注册时提供足够缓冲容纳撤销前在途数据；骤停场景不允许丢掉最后一个已接受 beat。
- REQ-005：复位清空有效状态；复位前未消费传输中止，由集成方协调接口重启，不能在释放时输出伪传输。
- REQ-006：payload 位宽至少一，模式/容量非法组合在生成或展开前拒绝；首版默认与支持上限在 G1 固化。
- REQ-007：通道种类、字段宽度和接口子集由 IP 开发套件明确并绑定实际 HWIF 契约；未完成此项不宣称标准协议兼容。
- REQ-008：验证连续满速、单拍脉冲、长背压、空满转换、中途复位和侧带全变化；报告各模式的真实吞吐与路径切分。

后续由 ip-development-suite 落实接口、参数、RTL 与验证，不按旧 CBB 分类将该条目重建回 CBB 仓。
