# 9. 同一个数为什么会有不同表示

[教学手册目录](index.md) · 下一章：[存储调度与性能](10-storage-performance.md)

读 PQC 代码最容易混淆的不是大公式，而是“这个数组现在装的是什么”。建议每次记录四项：数学域、系数表示、元素位宽、地址单位。

## 从噪声到字节

| 层次 | q=3329 的例子 | 转换是否丢信息 |
|---|---|---|
| 有符号小噪声 | -1 | 无；它是整数采样结果 |
| 模 q 的 canonical residue | 3328 | 对模 q 元素无损；不能再还原任意原始整数 |
| centered residue | -1，常用范围 -1664..1664 | 对模 q 元素无损 |
| NTT 域 | 整个多项式变为另一组系数 | 可逆；不是逐个给原系数改个编码 |
| 10-bit 压缩整数 | Compress10(3328)=0 | 有损；环绕舍入到零 |
| 10-bit 打包字节 | 按低位优先连续拼接 | 对压缩整数无损 |

`center(x)` 可先令 `x=x mod q`，若 `x>1664` 则减 q。压缩的整数实现为 `(((x mod q)·2^d + floor(q/2)) // q) mod 2^d`；解压为 `floor((q·y + 2^(d-1))/2^d)`。比较恢复误差要用模 q 的最短距离：3328 压成 0 再解成 0，误差是 1，不是 3328。

## 位宽要跟着运算增长

| 项目 | ML-KEM | ML-DSA | 工程含义 |
|---|---|---|---|
| q | 3329 | 8380417 | 切换参数不能只改编码长度 |
| canonical 系数最少位宽 | 12 | 23 | SRAM 用 32 bit 一槽不代表系数有 32 bit 有效数据 |
| 两系数相加的保守位宽 | 13 | 24 | 截断前先处理进位和模约减 |
| 两系数相乘的保守位宽 | 24 | 46 | 不能先窄截断再求模 |
| 256 系数的 32-bit 展开存储 | 1024 B | 1024 B | 计算布局与对外编码长度不同 |

Python 整数自动扩展，RTL 不会。`(a*b)%q` 在 Python 正确不代表窄位宽硬件表达式正确。减法同样要注意 unsigned 下溢以及 signed/unsigned 混用。

## NTT 域与 Montgomery 是两个维度

NTT 表示多项式经过变换；Montgomery 表示单个模数元素用 `xR mod q` 存储。二者可以组合，也可以各自单独使用。模型 [modular.py](../../pqc_accel_model/src/pqc_hw_model/modular.py)有 Montgomery 实验接口；当前 poly 详细设计采用普通 canonical 模表示，不能因为枚举名包含 `NTT_MONT` 就认定整条数据通路使用 Montgomery。

比较 NTT 中间值前须确认：正/逆变换方向、bit-reversal 顺序、KEM 的 128 个二次因子布局、是否带 R、逆变换缩放。只比较数组长度没有意义。

## 字节、word、页：三个坐标系

`byte_offset = word_address × 4`；`page = word_address // 256`；`coefficient_index = word_address % 256`。这是内部每系数一个 word 的布局。编码流里系数可跨字节和 word 边界，不能沿用一系数一 word 的解释。

例子：两个 12-bit 整数 `1,2` 打包为 `01 20 00`。第一个占 bit0..11，第二个占 bit12..23；这不是两个各占 16 bit 的整数。ML-KEM-768 公钥的 768 个系数占 1152 B，加 rho 的 32 B 才是 1184 B。展开后系数单独占 3072 B。

编码合法性也不等于长度合法性：12-bit 值 3329 能装进字节，却不是合法模 q 系数。模型 unpack 的 padding/系数检查不能替代命令层对整个输入长度的严格检查。

[bridge_demo.py](../examples/bridge_demo.py)会检查压缩的最大圆周误差、位宽与 packing 例子。检查题：0 与 3329 是否是同一个模数元素？数学上是，但公钥 canonical 编码不能接受 3329；协议对表示有额外约束。
