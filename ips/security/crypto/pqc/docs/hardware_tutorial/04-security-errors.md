# 4 · 用故障场景理解安全控制

[上一章](03-flows-memory.md) · [教学手册首页](index.md) · [下一章](05-verification-status.md)

先不要背所有错误码。把错误理解为三类：公开输入不合法、算法本来允许的无效结果、硬件无法继续可靠执行。三类处理不同，混淆它们会导致信息泄漏或错误发布。

## 4.1 三个最容易混淆的结果

| 场景 | 应如何理解 |
|---|---|
| KEM 密文长度不对 | 输入格式错误，可以拒绝命令 |
| KEM 正确长度密文重加密不匹配 | 隐式拒绝，仍返回 32 B 派生秘密，不公开失配位 |
| DSA 签名无效 | 验签的合法公开结果，可报告 VERIFY_INVALID |

DMA 返回错误、不可纠正 ECC、熵健康异常等不属于密码学“正常拒绝”。系统不能因为它们发生就返回一个看似成功的签名或共享秘密。

## 4.2 状态码是什么，错误码又是什么

[pqc_pkg.sv](../../rtl/pqc_pkg.sv) 定义 completion status：SUCCESS=0、VERIFY_INVALID=1、CONFIG_ERROR=2、DMA_ERROR=3、RNG_ERROR=4、FATAL=5。它描述总体类别。

同一文件定义更具体的 error code，例如 BAD_OPCODE=0x01、BAD_PARAMSET=0x02、BAD_ABI=0x03、BAD_ALIGN=0x04、BAD_LENGTH=0x05、BAD_CAPACITY=0x06、BAD_KEY=0x07、PERMISSION=0x08、DMA=0x10、RNG=0x11、SELFTEST=0x12、INTERNAL=0x20、RETRY_EXHAUST=0x21、ECC_UE=0x22。

“枚举已定义”不代表每个分支已经被完整顶层测试覆盖。阅读某条路径时，继续追踪产生者、锁存位置、completion 编码和测试期望。

## 4.3 场景一：密钥导入只来了一半

硬件不能在导入开始时就将材料标为 READY。长度、last、完整性和授权信息都确认后，才允许算法使用。失败时要清除已经写入的部分和暂存，不能留下“槽有效但材料不完整”的状态。

Key Slots 管授权元数据，Work Key RAM 管私钥字节，两者需要绑定。Python 模型中的一个字典 Slot 同时保存这些概念，是学习便利，不应照搬成硬件边界。

## 4.4 场景二：新生成密钥已传出，但 ACK 错了

当前 `pqc_key_custody` 候选依次 HEADER→REQUEST→WAIT_DATA→STREAM→ACK。它对 transaction、epoch、handle、owner、domain 和 bytes 比对；错误身份不会推进成功，超时仍然适用。

对学习者而言，关键问题是“谁说已经保存好了私钥”。不是本地 generated_last，不是 word_ready，而是可信接收方针对正确事务的最终 ACK。普通导入的已有私钥不能借此变成通用读回。

## 4.5 场景三：总线停止 ready

ready=0 时，当前数据还没有被接受，游标不能前进，last 不能丢失。如果数据来自 SRAM，内部可以预取，但必须有足够保持槽，确保输出稳定和返回归属正确。

取消发生时，已经送出的 AXI 事务可能仍需排空。停止产生新请求和确认全部旧响应结束是两件事。永久背压下，超时锁定比伪造成功更符合安全边界。

## 4.6 场景四：旧命令的 done 迟到了

假设命令 A 正在等待 NTT，随后被撤销，命令 B 开始。若 A 的 done 到来时硬件只检查“Poly done=1”，B 可能错误推进。epoch/token 的目的就是将响应绑定到正确命令和原语。

这个问题也发生在签名重试之间：上一次 attempt 的 norm_ok 不得被本次候选继承。因此每次尝试要清 done 与累积位，匹配身份后才能写新的结果。

## 4.7 场景五：清零与结果写回同拍

目标优先级是清除/撤销先屏蔽正常副作用。不能先发出敏感结果 valid，再认为“下一拍会清”。清除范围包括数据 RAM、ECC、标签、FIFO 实体、hash 状态、采样/编码暂存和随机缓存。

主算法 FSM 可能损坏，因此 Fault/Zeroize 控制独立存在。各模块完成清除的 ACK 要汇总；仅发过请求或将计数器置零都不等于物理数据已擦掉。

## 4.8 从功能安全走向泄漏防护

ECC 关注数据错误，权限关注越权，常数时间关注秘密相关的控制/访问，掩码关注数据相关泄漏。这些目标互补。尤其受保护 Keccak 的局部测试不能证明 Codec、Sampler、Poly、Key RAM 到输出的全秘密链路都安全。

更多两 share、HPC3+、A2B/B2A 与随机预算的讲解见[安全基础章](../learning/10-security.md)。这里的学习目标是看到一个信号或缓冲时，能判断它是公开控制、秘密数据，还是仍不得公开的候选结果。

## 练习

画出“导入成功→授权使用→撤销→清除→重新导入”的时间线。在每个时刻问：旧 handle 可否使用？RAM 是否仍有旧字节？总线是否还有未返回事务？只有把授权撤销、物理擦除和总线排空分开回答，才算读懂安全收尾。
