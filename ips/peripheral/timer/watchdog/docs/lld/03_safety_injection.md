# Watchdog：诊断注入、低功耗与物理约束

## 一次真实注错

FAULT_INJECT 需DIAG_INJECT_EN、SAFETY_EN、test_auth、捕获的cfg/diag_auth、未DIAG_LOCK
和当前有效来源绑定额度；处理时一次消费额度。目标0翻主C的一位，1翻主D，2翻
TIMEOUT保护副本；位索引先按实际宽度检查。目标3写预定义非法状态6/7，4/5仅翻
下一次检查的一个比较结果，要求索引0。目标/索引不合法返回BAD_CONFIG且不注错。
增强检测不存在时返回UNSUPPORTED，不借注入直接置最终故障来伪造检测覆盖。

注入后由真实下一拍检测观察异常，走正常原因/请求锁存；不可持续屏蔽真实错误。
设置TEST_CONTEXT早于该异常FIRST捕获，真实原因仍完整记录。IRQ_TEST仅中断事件，
不证明比较器；生产可裁掉注入入口。timebase测试应使用未承担生产监督的专用通道。

## 功耗与隔离

只对运行计时、序列、客户端Deadline做同步clock-enable。暂停不门控安全比较、升级
E、解锁额度和事件保持；不从组合逻辑生成新时钟。无内部电源岛、retention宏和SRAM，
故MBIST为NA。scan/test时钟切换由系统DFT控制，不能让普通软件取得scan旁路。
外部停钟/失电与共因由系统安全分析覆盖；不能宣称ASIL等级或固定诊断覆盖率。

## 综合和门级检查意图

主/影子状态、独立服务资格和final_hold保持不同逻辑锥；keep/dont_touch与物理分隔
要求进入综合/布局约束。综合网表应按寄存组数量、不同驱动锥、跨副本共用逻辑、
最终请求独立可达性核查；仅RTL命名不同不算证据。真实PPA按三个产品档分别报告
面积/时序/功耗及输入库corner/活动假设，当前100/50MHz只是表征输入。
